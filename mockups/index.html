NotchSend: mockup di setiap action

16 state yang dirender persis seperti posisi aslinya: nempel di notch fisik MacBook Air, di bawah menu bar. Semua angka, nama file, dan nama device di halaman ini data contoh buat review visual, bukan data asli.

Arah visual ngikutin DynamicNotch apa adanya: permukaan hitam notch, teks putih, biru sistem cuma buat aksi utama dan progress, warna lain cuma buat status. Ikon pakai glyph sekelas SF Symbols, tidak ada emoji. Ukuran tombol aksi minimal 36px (Fitts), pilihan peer dibatasi yang online di atas (Hick), dan state yang lagi jalan selalu kelihatan tanpa buka window (visibility of system status).

M16Daemon bermasalah (port / mati)

Trigger: daemon_status bermasalah, atau socket IPC tidak bisa dihubungi. Ditampilkan di halaman M15, bukan modal yang mengganggu.

Tutup aplikasi LocalSend, NotchSend akan mengambil alih port-nya sendiri dalam 30 detik. Mengirim file tetap bisa selama daemon jalan.
Varian lain, layout sama: "Daemon tidak jalan" (tombol: Jalankan daemon) / "Izin Local Network ditolak" (tombol: Buka Pengaturan Sistem) / "Daemon versi lama, lagi diperbarui" (tanpa tombol, hilang sendiri).
  • Tidak pernah muncul sebagai kartu yang menyela. User taunya dari dot status di M15 berubah kuning, dan dari ikon menu bar.
  • Daemon tetap retry bind port tiap 30 detik di belakang layar, sesuai blueprint §11.

Cara review: koreksi per nomor (mis. "M01 tombol Tolak jangan abu, bikin sejajar", "M06 peer offline buang aja"). Nomor mockup ini yang nanti jadi acuan nama view di kode Swift: M01 = LocalSendConfirmView, M02/M10 = LocalSendMinimalView, M03/M11 = LocalSendExpandedView, dan seterusnya.

Yang sengaja tidak ada mockup-nya: request masuk ke-2 saat lagi ada transfer (daemon langsung balas 409 ke pengirim, notch user tidak menampilkan apa-apa, pengirim yang melihat "sibuk"), dan notifikasi Lock Screen (di luar scope v1 di blueprint).
